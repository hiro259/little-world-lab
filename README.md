# Little World Lab

A tiny 3D world built together with AI.

言葉から育つ、小さな3Dワールド。参加者のアイデアを、その場でゲームの機能へ変えていくライブ開発デモです。

## Stack

- [Three.js](https://threejs.org/) — WebGL 3D rendering
- Vanilla JavaScript (ES modules)
- [Vite](https://vite.dev/) — local development and static production build
- Cloudflare Pages — planned hosting (see [Issue #2](https://github.com/hiro259/little-world-lab/issues/2))

No backend, login, multiplayer, or external 3D assets are required.

## Worlds

Click the **WORLD** badge in the top-right corner (or focus it and press Enter/Space) to switch between:

- **WORLD 01 — はじまりの草原:** the original 44×44 grassy square, with three tiny mushrooms.
- **WORLD 02 — 海辺の草原:** the same 44×44 square, split **half land (+Z) / half sea (-Z)**, with a small sandy shoreline and gentle surface ripples.

The selection is kept in the URL (WORLD 02 uses `?world=02`). Switching worlds reloads the scene to start from a known, safe position. WORLD 02 starts on land and prevents walking into the ocean; swimming is not implemented yet. You can share the link to a specific world.

## Requirements

- Node.js **22.12+** (or Node.js 20.19+)
- npm
- A desktop browser with WebGL support

## Run locally

    npm install
    npm run dev

Open the URL printed by Vite (usually http://localhost:5173/).

Controls:

- **WASD / arrow keys:** walk (relative to camera direction).
- **Shift + ← / →:** rotate camera left / right around the player.
- **Shift + ↑ / ↓:** raise / lower the camera viewing angle (with safe angle limits).
- **Ctrl (press once):** toggle first-person Point of View (POV) mode on/off. Release Ctrl before using the arrows; Ctrl+arrows can trigger macOS desktop shortcuts.
- **POV mode, ← / →:** look left/right; **↑ / ↓:** look up/down (with pitch limits).
- **POV mode, WASD:** walk relative to the viewing direction. Arrow keys look around rather than walking.
- Click the **操作方法** panel to collapse it into a small button; click again to expand.

The camera continues to follow the character while orbiting. In POV mode the camera moves to the character's eye level and hides the avatar (so the head does not block the view); pressing Ctrl again restores the third-person camera. Refreshing resets the initial viewing angle.

## Build

    npm run build
    npm run preview

The static production site is generated into `dist/`. In Cloudflare Pages, configure:

| Setting | Value |
| --- | --- |
| Framework preset | Vite (or None) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Production branch | `main` |

No environment variables or server-side components are needed. Cloudflare setup and deployment are tracked in [Issue #2](https://github.com/hiro259/little-world-lab/issues/2). Follow the [step-by-step Cloudflare Pages guide](docs/cloudflare-pages.md) to connect GitHub, deploy, and roll back. The public URL is assigned by Cloudflare after the first successful deployment.

> The dependency lockfile is intentionally not generated by hand. Run `npm install` to create `package-lock.json` and commit it as part of the upcoming CI setup in Issue #3. Until then, the lightweight smoke-build workflow uses `npm install`.

## Adding something to the world

Both worlds currently contain **just three tiny mushrooms** on the land, and no animals, trees, houses, or ponds. The second world also has a sea and beach; later audience requests can add more objects. Those larger changes will be part of the interactive presentation.

`World.addObject(item, position)` provides an entry point:

```js
const mesh = new THREE.Group();
// Add your own basic-shape meshes to the group here.
world.addObject(mesh, [3, 0, -2]);
```

It also accepts an object of shape `{ mesh, update(delta, context) }` for simple animation/behavior. The game loop calls the registered item's `update` method every frame. Keep each new animal or prop in its own file under `src/objects/` when adding features (Issue #6 will expand this into a reusable template).

## Development workflow

1. Create an Issue with a small, visible change.
2. Create a feature branch.
3. Make the change, run `npm run build`, and open a PR.
4. Preview it and merge to `main` when ready.
5. Cloudflare Pages publishes the new `main` version after each merge. Visitors refresh their browsers to see it.

For safety, do not push work-in-progress features directly to `main`.
